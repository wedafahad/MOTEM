# متم — نظام تقييم فريق الكتابة (كناية)

نظام تقييم ربعي تفاعلي لفريق كتّاب كناية، مبني وفق [استراتيجية تطوير وتقييم فريق الكتابة](.) وبهوية Kenayah البصرية (الألوان، وخط Ghroob، والشعار).

- **الواجهة**: `web/` — HTML/CSS/JS خالص، بدون أطر عمل أو خطوة بناء (Build)، تُستضاف كملفات ثابتة على GitHub Pages.
- **قاعدة البيانات**: Google Sheets عبر Google Apps Script (`api/Code.gs`) — تعمل من أي جهاز وأي حساب، بدون localStorage وبدون ربط بحساب Claude.
- **خادم اختبار محلي**: `api/mock_server.py` — لتجربة الواجهة على جهازك قبل نشر Apps Script الحقيقي فقط. **لا يُستخدم في الإنتاج.**

---

## 1) نشر قاعدة البيانات (Google Apps Script + Sheets)

1. افتحي [sheets.google.com](https://sheets.google.com) وأنشئي جدول بيانات (Spreadsheet) جديدًا فارغًا، سمّيه مثلًا **"متم — قاعدة البيانات"**.
2. من القائمة: **الإضافات (Extensions) ← Apps Script**.
3. احذفي أي كود موجود في `Code.gs` الافتراضي، والصقي بدلًا منه محتوى الملف [`api/Code.gs`](api/Code.gs) من هذا المستودع بالكامل.
4. احفظي المشروع (Ctrl/Cmd+S)، وسمّيه "متم API".
5. من القائمة العلوية في محرر Apps Script: اختاري الدالة **`setupInitialData`** من القائمة المنسدلة بجانب زر ▶ Run، ثم اضغطي **Run**.
   - أول مرة سيطلب منك Apps Script صلاحيات (Authorize) — وافقي (هذا مشروعك الخاص، لا بيانات ترسَل لأي جهة خارجية).
   - بعد التنفيذ، افتحي **View ← Logs** (أو Ctrl/Cmd+Enter) لرؤية:
     - **كلمة مرور الإدارة العامة**
     - **الأكواد الشخصية** لكل موظف (كاتب/مقيّم) — انسخيها فورًا، لن تظهر هنا مرة أخرى بهذا الشكل (لاحقًا تقدرين تسترجعينها من شاشة «الموظفون» بصلاحية الإدارة داخل التطبيق نفسه).
6. **انشري التطبيق كـ Web App**:
   - **Deploy ← New deployment**.
   - نوع النشر (Select type): **Web app**.
   - Execute as: **Me**.
   - Who has access: **Anyone** (ضروري ليعمل النظام من أي جهاز بدون تسجيل دخول Google).
   - اضغطي **Deploy**، ووافقي على الصلاحيات مرة أخرى إن طُلب.
   - انسخي **رابط Web App URL** الناتج (ينتهي بـ `/exec`) — هذا هو رابط الخادم (`API_URL`) الذي ستُدخلينه في الواجهة.

> **تحديث الكود لاحقًا؟** عدّلي `Code.gs` في المحرر، ثم **Deploy ← Manage deployments ← ✏️ تعديل ← نسخة جديدة (New version) ← Deploy**. رابط `/exec` نفسه يبقى ثابتًا ولا يتغيّر.

### مشاركة نفس القاعدة مع عضو آخر بالفريق
فقط شاركي رابط `/exec` نفسه معه — لا حاجة لأي صلاحيات Google Sheets، فالتطبيق يتحدث مع الرابط مباشرة بمعزل عن صلاحيات الشيت.

## 2) نشر الواجهة (GitHub Pages)

### الحالة أ: ليس لديك مستودع بعد
```bash
cd "متم"
git add -A
git commit -m "إطلاق نظام متم"
```
ثم على [github.com/new](https://github.com/new) أنشئي مستودعًا جديدًا (خاص أو عام)، ثم:
```bash
git remote add origin https://github.com/<username>/<repo>.git
git branch -M main
git push -u origin main
```
بعدها من إعدادات المستودع: **Settings ← Pages ← Source: Deploy from a branch ← Branch: main، المجلد: `/web`** ← Save.
سيظهر الرابط الدائم خلال دقيقة على شكل: `https://<username>.github.io/<repo>/`

### الحالة ب: لديك مستودع جاهز
أخبريني باسم المستودع (`owner/repo`) وسأجهّز لك الملفات لدفعها إليه مباشرة، أو أعطيك أوامر `git remote add` + `push` جاهزة لتشغيلها بنفسك.

## 3) الربط بين الواجهة والخادم

1. افتحي رابط GitHub Pages (أو `web/index.html` محليًا للتجربة).
2. في شاشة **"إعداد الاتصال بقاعدة البيانات"** الصقي رابط `/exec` من الخطوة (1) واضغطي **حفظ ومتابعة**.
3. سجّلي الدخول بأي كود من الأكواد التي حصلتِ عليها من `Logger`.

هذا الإعداد يُحفظ في متصفح كل مستخدم مرة واحدة فقط (رابط الخادم، وليس بيانات العمل).

## 4) الأدوار وبيانات الفريق المبدئية

| الاسم | الدور | يُقيَّم من |
|---|---|---|
| المدير | مقيّم (مدير أعلى) | — |
| وداد الدريني | كاتبة أولى + مقيّمة | المدير |
| ميمونة المرشد | كاتبة | وداد الدريني |
| حمزة السويلم | كاتب | وداد الدريني |
| أفنان الأسمري | كاتبة | وداد الدريني |
| سارة القحطاني | كاتبة | وداد الدريني |
| أحمد بكري | كاتب | وداد الدريني |

- **كاتب**: يسجّل دخوله بكوده الشخصي، يرى لوحته وسجل أعماله فقط، يقيّم نفسه ذاتيًا على مؤشرات التفاعل، ولا يرى تقييمه التفصيلي إلا بعد الاعتماد.
- **مقيّم/مدير مباشر**: يسجّل دخوله بكود منفصل، يرى فريقه المباشر فقط، يقيّمهم، ويرى/يعتمد أيضًا تقييمات الفريق الذي تحت إشراف من يقيّمهم هو (تدقيق على مستويين، تمامًا كآلية التعاير في الاستراتيجية).
- **إدارة عامة**: كلمة مرور منفصلة، تدير الموظفين والتسلسل الهرمي والمعايير والأوزان وسجل التعديلات، لكن **لا** ترى تفاصيل أي تقييم (فقط الحالة والدرجة الإجمالية) — الخصوصية مطبَّقة من الخادم نفسه لا الواجهة فقط.

إضافة/حذف موظفين، وتعديل التسلسل الهرمي، كلها من شاشة **«الموظفون»** بصلاحية الإدارة. المعايير والأوزان والحدود الدنيا (Bands) كلها قابلة للتعديل من شاشة **«المعايير والأوزان»**، مع زر **"اقتراح تلقائي"** يقترح حدودًا بناءً على متوسط أداء الفريق الفعلي لكل ربع.

## 5) التطوير المحلي (اختياري)

```bash
python3 api/mock_server.py     # خادم اختبار محلي على http://localhost:8787
python3 -m http.server 5500 --directory web   # أو عبر preview_start في Claude Code
```
افتحي `http://localhost:5500`، واختاري "استخدام الخادم المحلي" في شاشة الإعداد. بيانات هذا الخادم تُخزَّن في `api/data/db.json` (مستبعد من Git) — لا علاقة له بالإنتاج.

---

## 6) قيود معروفة وأفكار للتوسعة لاحقًا

- **الأعمال التشاركية**: البنية تدعم مبدئيًا حقل `collaborators` بنسبة توزيع، لكن لا توجد بعد واجهة لإضافة أكثر من كاتب على نفس العمل — التوزيع يفترض حاليًا 100% لصاحب العمل. يمكن إضافتها لاحقًا في نموذج «إضافة عمل».

هذه النقطة لا تمنع الاستخدام الفعلي للنظام اليوم، لكنها تحتاج جولة تطوير إضافية إن أردتِ تفعيلها بالكامل.
